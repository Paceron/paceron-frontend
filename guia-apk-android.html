📱 Guía: Generar APK de Android

App Paceron (Expo) — paso a paso para principiantes

¿Qué vamos a hacer?

Vamos a compilar tu app de Expo en un archivo APK (el formato de instalación de Android) y luego pasarlo a tu teléfono para instalarlo. Todo se hace desde tu Mac.

💡 No necesitas publicar nada en Google Play. El APK se instala directamente en tu teléfono.

Parte 1 — Preparar la Mac (solo la primera vez)

1

Exportar la ubicación del Android SDK

Tu Mac ya tiene el Android SDK instalado, pero la terminal no sabe dónde está. Abre una terminal y ejecuta:

export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

Para no tener que hacerlo cada vez, guárdalo en tu configuración:

echo 'export ANDROID_HOME="$HOME/Library/Android/sdk"' >> ~/.zshrc
echo 'export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"' >> ~/.zshrc
source ~/.zshrc

Comprueba que funcionó:

echo $ANDROID_HOME && adb version
Si ves una ruta y la versión de adb, todo está bien.
2

Iniciar sesión en Expo

El programa que compila (EAS CLI) necesita una cuenta gratuita de Expo:

npx eas-cli login

Te pedirá email y contraseña. Si no tienes cuenta, créala en https://expo.dev/signup (es gratis).

Parte 2 — Generar el APK

3

Elegir qué APK quieres

Hay dos comandos disponibles. Elige uno según lo que necesites:

Quiero… Comando Resultado
Probar la app (desarrollo) npm run eas:build:android:preview:local APK "Paceron Dev" (ícono ámbar)
Versión final (producción) npm run eas:build:android:production:local APK "Paceron" (ícono blanco)

Ejecuta el que elijas desde la carpeta del proyecto:

npm run eas:build:android:preview:local
⏳ La primera vez puede tardar varios minutos porque descarga dependencias de Gradle. Es normal.
4

Localizar el APK generado

Al terminar, se crea una carpeta builds/ con el archivo:

builds/paceron-preview-v0.33.0.apk
builds/paceron-production-v0.33.0.apk

¡Ese es el archivo que vas a instalar en tu teléfono!

Parte 3 — Pasar el APK al teléfono

5

Elige una forma de transferirlo

Opción A — Cable USB (la más directa)

Conecta el teléfono por USB, activa "Depuración USB" en las opciones de desarrollador del teléfono, y ejecuta:

adb install builds/paceron-preview-v0.33.0.apk

El APK se instala automáticamente.

Opción B — Enviar el archivo

  • Google Drive / Dropbox: sube el APK y descárgalo desde el navegador del teléfono.
  • WhatsApp / Telegram: envíate el archivo a ti mismo.
  • Email: adjunta el APK y ábrelo desde el correo en el teléfono.

Opción C — Descarga por WiFi (sin cables)

Sirve la carpeta desde tu Mac y descarga desde el navegador del teléfono (ambos deben estar en la misma red WiFi):

cd builds && python3 -m http.server 8080

Luego en el teléfono abre http://IP-DE-TU-MAC:8080 y toca el APK.

Para saber la IP de tu Mac ejecuta: ipconfig getifaddr en0
6

Instalar en el teléfono

Al abrir el APK por primera vez, Android pedirá permiso para "instalar apps de origen desconocido" para la app que usaste (navegador, Drive, etc.).

  1. Activa ese permiso cuando te lo pida.
  2. Vuelve a abrir el APK.
  3. Toca "Instalar".
✅ Listo. Ya tienes la app instalada en tu teléfono.

Parte 4 — Diferencia entre APK de desarrollo y de producción

DESARROLLO APK de desarrollo (preview)

  • Nombre visible: "Paceron Dev".
  • Ícono: ámbar (para distinguirlo a simple vista).
  • Package: com.paceron.app.dev — distinto al de producción.
  • APP_VARIANT: development.
  • Para qué sirve: probar cambios, depurar, compartir con testers.
  • Ventaja clave: se puede instalar junto a la versión de producción en el mismo teléfono (no se sobrescriben) porque tienen package distinto.
  • Limitación: incluye herramientas de depuración; no es la versión que publicarías.

PRODUCCIÓN APK de producción

  • Nombre visible: "Paceron".
  • Ícono: blanco (el oficial).
  • Package: com.paceron.app.
  • APP_VARIANT: production.
  • Para qué sirve: la versión final que usarás tú o tus usuarios.
  • Ventaja clave: optimizada, sin herramientas de depuración, lista para distribuir.
  • Requisito: necesita un keystore de firma configurado en EAS (la primera vez te preguntará si quieres generar uno nuevo — responde "Yes").
Resumen en una frase: el APK de desarrollo es para probar (se instala junto al oficial y tiene ícono ámbar), y el de producción es la versión final (ícono blanco, optimizada, la que compartirías con usuarios).

Consejo rápido

Si solo quieres probar rápido sin generar un APK, conecta el teléfono por USB y ejecuta:

npm run android

Esto compila e instala directamente en el dispositivo conectado (sin generar archivo compartible).

⚠️ El perfil de producción requiere que las credenciales de firma (keystore) estén configuradas en EAS. Si es la primera vez, EAS te preguntará si quieres generar un keystore nuevo — responde "Yes".

Parte 5 — Alternativa: Build local sin EAS (sin cuenta Expo)

Úsalo si EAS te da error de permisos ("Entity Not Authorized"). Compila el APK en tu Mac con Gradle, sin nube ni cuenta Expo.
1

Preparar el proyecto (prebuild)

Genera la carpeta android/ con la configuración actual:

npx expo prebuild --platform android
Si ya existe la carpeta android/, este paso puede pedir confirmación para sobrescribir. Responde "Yes" solo si no tienes cambios manuales en android/.
2

Compilar el APK con Gradle

Entra a la carpeta android y ejecuta:

cd android
./gradlew assembleRelease

Para un APK de debug (más rápido, sin firma):

./gradlew assembleDebug
⏳ La primera vez descarga dependencias de Gradle y puede tardar varios minutos.
3

Localizar el APK

El archivo queda en:

android/app/build/outputs/apk/release/app-release.apk
android/app/build/outputs/apk/debug/app-debug.apk
4

Instalar en el teléfono

Conecta el teléfono por USB con depuración USB activa y ejecuta:

adb install android/app/build/outputs/apk/release/app-release.apk

O transfiere el archivo por Drive/WhatsApp/cable y ábrelo en el teléfono (activa "instalar apps de origen desconocido").

💡 El build local no necesita cuenta Expo ni EAS. Solo requiere tener instalado el Android SDK y JDK. La URL del backend ya quedó configurada en .env y eas.json.
